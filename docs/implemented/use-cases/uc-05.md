# Báo cáo triển khai Use Case: UC-05 Send Message

## 1. Mô tả chi tiết
Use case **Send Message (Chat cá nhân/Nhóm/Toàn mạng)** phụ trách việc nhận tin nhắn từ Client, lưu trữ vào CSDL để bảo toàn dữ liệu và định tuyến (Routing) gói tin đến người nhận phù hợp dựa vào `TargetType`.
Server luôn **ghi tin nhắn vào Database (Entity Framework)** trước khi phân phối, điều này đảm bảo tính nhất quán (Consistency) kể cả khi người nhận hiện không Online (họ có thể lấy lại qua UC-10: Chat History).

## 2. Thiết kế lớp chi tiết (Class Design)
Sơ đồ lớp chi tiết của tiến trình gửi và định tuyến tin nhắn:

```mermaid
classDiagram
    class IMessageHandler {
        <<interface>>
        +RoutingKey: string
        +HandleAsync(session: SessionHandler, payload: JsonElement) Task
    }

    class ServerChatHandler {
        +RoutingKey: string = "chat.msg"
        -_serviceProvider: IServiceProvider
        -_sessionManager: SessionManager
        +HandleAsync(session: SessionHandler, payload: JsonElement) Task
    }

    class AppDbContext {
        +Users: DbSet<User>
        +ChatGroups: DbSet<ChatGroup>
        +GroupMembers: DbSet<GroupMember>
        +Messages: DbSet<Message>
        +SaveChangesAsync() Task<int>
    }

    class Message {
        +Id: Guid
        +SenderId: Guid
        +ReceiverId: Guid?
        +GroupId: Guid?
        +Content: string
        +SentAt: DateTime
    }

    class SessionManager {
        +TryGet(username: string, out session) bool
        +Snapshot() Dictionary<string, SessionHandler>
    }

    IMessageHandler <|-- ServerChatHandler
    ServerChatHandler ..> AppDbContext : Lưu Message & Truy vấn Target
    ServerChatHandler --> SessionManager : Xác định và định tuyến đến Session Online
    AppDbContext --> Message : Quản lý Entity
```

## 3. Biểu đồ tuần tự (Sequence Diagram)
Biểu đồ tuần tự mô tả chi tiết quá trình Server nhận, lưu trữ và định tuyến một tin nhắn.

```mermaid
sequenceDiagram
    participant Sender as Client (Người gửi)
    participant Server as LanChat Server
    participant Handler as ServerChatHandler
    participant DB as AppDbContext
    participant SManager as SessionManager
    participant Receiver as Client (Người nhận)
    
    Sender->>Server: Packet [RoutingKey="chat.msg", Payload=ChatMessagePayload]
    Server->>Handler: HandleAsync(Payload)
    activate Handler
    
    Handler->>DB: Truy vấn thông tin người gửi (SenderId)
    Handler->>DB: Truy vấn thông tin đích đến (ReceiverId / GroupId) tùy TargetType
    activate DB
    DB-->>Handler: Target Info
    deactivate DB
    
    Handler->>Handler: Khởi tạo Entity Message
    Handler->>DB: Messages.Add(messageEntity)
    Handler->>DB: SaveChangesAsync()
    activate DB
    DB-->>Handler: Lưu thành công (ServerMessageId sinh ra)
    deactivate DB
    
    Handler-->>Sender: Packet [RoutingKey="chat.echo", Payload=ChatEchoPayload] (Xác nhận đã lưu)
    
    alt TargetType == "PRIVATE"
        Handler->>SManager: TryGet(TargetId)
        alt isOnline == true
            Handler->>Receiver: Packet [RoutingKey="chat.receive", Payload=ChatMessageDto]
        end
    else TargetType == "ALL"
        Handler->>SManager: Snapshot()
        loop Mỗi session trừ người gửi
            Handler->>Receiver: Packet [RoutingKey="chat.receive"]
        end
    else TargetType == "GROUP"
        Handler->>DB: Lấy danh sách thành viên Group
        DB-->>Handler: GroupMembers
        loop Mỗi thành viên trừ người gửi
            Handler->>SManager: TryGet(Member.Username)
            alt isOnline == true
                Handler->>Receiver: Packet [RoutingKey="chat.receive"]
            end
        end
    end
    
    deactivate Handler
```

## 4. Lưu ý
Hiện tại Client đang bỏ qua việc xử lý gói tin "chat.echo" sau khi nhận được từ Server, nếu cần chi tiết hơn thì sẽ cần lưu lại ClientMessageId của ChatMessagePayload khi gửi và so sánh với ClientMessageId của ChatEchoPayload khi nhận để xác định gói tin echo tương ứng.
